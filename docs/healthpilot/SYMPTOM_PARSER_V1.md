# 阶段 1B：可核对的中英文症状解析草稿

## 范围和保存边界

本阶段在阶段 1A 的新增记录表单中提供“解析为草稿”。使用确定性规则和小型普通语言词典，解析器与词典版本均为 `1.0.0`。不调用 AI 模型、供应商或付费服务，不需要 API Key，不向外部网络发送健康原文或结构化内容。认证 API key 仍可按既有认证流程访问接口，它不是模型密钥。

解析是临时预览，不能创建、编辑或删除记录。界面展示建议、原文依据、可翻译的匹配理由，以及“明确匹配”“需要确认”“未识别”；不显示百分比置信度。用户可以手工修改、清空所有字段，修改后标记为“用户填写”。只有明确点击“核对并保存”才调用阶段 1A 的严格创建接口。保存后继续使用既有查询、编辑、版本冲突和永久删除功能。

完全手工录入始终可用，包括词典未收录的症状和解析服务不可用的情形。新记录的开始时间保持空白，状态默认未知，强度未知使用空值。无法提供开始时间时暂时不能保存。已结束事件仍必须有不早于开始时间的结束时间。

## 支持表达和保守处理

词典覆盖头痛、肩颈不适、肩痛、颈部疼痛、腰背或臀部不适、腹胀、恶心、疲劳，以及有限中英文同义表达；它不是临床分类或疾病编码。身体部位只匹配原文明确表达。诱因与缓解因素首版覆盖久坐、运动、进食，以及休息、走动、喝水、热敷等有限表达；仅记录用户描述的关联，不作医学因果判断。

- 明确的整数量表如 `4/10`、`0/10` 可建议强度；“很疼”“不太疼”不转换成数字。负数、范围（如 `3-4/10`）、范围外数值和多个不同数值需要确认。
- “没有头痛”排除肯定候选；“没有头痛，但是有点恶心”保留恶心候选。描述他人、假设或未来事件时，排除相关内容。规则偏向少识别，不能替代对整段自然语言的理解。
- 识别到多个不同症状时，不自动选第一个、不合并、不批量保存；列出候选，用户选择一个事件，并自行填写其余字段。相同词典类别的重复提及不代表多个事件，复杂叙述建议分次手工记录。只有一个已知候选但存在“和 / and / 、”等并列连接词时保守拒绝自动填值，防止默默丢弃词典外症状。
- “最近”“有一阵子”“昨晚”保留为待确认线索。“持续两小时”只作线索，不新增 duration 字段，不推断结束状态或结束时刻。“缓解”“好一点”不等于结束。
- 缓解因素支持“热敷后好多了”“热敷以后好转了一些”“休息后舒服些／舒服多了”“喝水后症状减轻”等已发生的改善描述；不将否定、恶化、计划、假设、疑问或他人经历当成本人的有效缓解。没有明确症状名称时可预览缓解因素，但仍需手工补填症状名称才能保存。改善只表示用户描述的关联，不代表医学因果或症状已结束。
- 英文否定缩写（包括弯引号）与中文否定、子女描述也会被排除。工作或活动的结束不能作为症状结束的依据；活动后缓解不填为诱因。带有“大约 / 左右 / approximately”、备选时刻或时间范围的表达保持待确认。
- HTML、代码、链接、SQL 和部分指令式表达保守返回不支持提示，仍允许手工记录。所有原文都按普通文本展示，不执行或渲染 HTML、Markdown、链接和指令。

## 时间与时区

服务器在每次解析开始时固定参考时刻，只读取当前认证用户的已保存时区偏好；不读取其他健康历史。有效偏好标记为 `user_preference`。时区缺失、无效或查询失败时返回 `timezone: null` 和 `timezone_source: unconfirmed`，不将兼容旧接口的 UTC 回退伪装成已确认时区。参考时刻、实际时区和来源均在预览中展示。

相对日期先按该时区的日历日期计算，再解释足够明确的时刻。例如“昨天下午3点开始头痛”或“Headache started yesterday at 3 pm”。首版支持今天/昨天、ISO 日历日期、明确上下午或 24 小时钟，并要求原文给出开始/结束语义。无上下午的“昨天3点”、只有日期、只有时长等保持待确认。跨午夜和跨年使用共享日历工具。

本地时刻解析检查时钟转换两侧的偏移。夏令时跳过的时刻不自动平移，重复时刻不默认选择早或晚的一次；显示警告。手工输入也拒绝不存在或重复的本地分钟。首版没有按 UTC 偏移选择重复时刻的控件，需提供另一明确时刻；已保存记录未改动的原有时间继续保留其绝对时刻。

## 原文、生命周期和隐私

保存沿用阶段 1A 原文契约，完整保留最终提交的字符串，包括空格、换行、中文、组合字符和 emoji；不修剪、翻译或摘要。保存后的结构化编辑不能覆盖原文。原文长期保留与删除边界沿用阶段 1A：永久删除记录或删除账户移除在线记录，已有备份仍服从部署方的备份保留与销毁规则；本阶段不改变备份系统。

未保存草稿仅保留在当前表单组件内存中，不写入 URL、localStorage、IndexedDB、聊天记录、查询持久化或离线队列。更改原文立即作废旧预览、依据和自动填值；手工填写的字段继续标记为用户输入。使用原文修订号、请求序号和卸载守卫拒绝旧响应，不覆盖用户填写。取消、离开、刷新、退出登录、账号或身份切换后清除草稿，离开未保存内容前提示。语言切换只改变界面文字。没有自动重试、后台重解析、自动学习或自动保存。

解析输入、候选、证据和输出均是健康内容。后端日志只保留安全请求状态、固定错误类别和耗时；认证异常、JSON/schema 错误、未知或编码子路径均不回显健康内容。前端 API helper 关闭该领域内容日志并净化错误，避免全局 Query/Mutation 错误处理间接泄漏。过期请求取消不弹错误提示。

## 接口与实现

`POST /api/v2/symptom-journal/parse` 位于 `/:id` 路由之前，继承 cookie/API key 认证和 owner-only 边界。未认证返回 401；切换身份、委托和 on-behalf-of 返回 403，家庭、报告和管理员没有例外。客户端不能提交 owner、其他用户、记录 ID、时区、参考时刻或供应商参数。响应设置 `Cache-Control: no-store`。

请求只有 `raw_text` 和 `locale`（`en` / `zh`），原文最多 10000 个 JavaScript UTF-16 code units；该路径在通用 JSON parser 前使用 64 KiB 请求体上限。预览独立于严格创建契约，允许结构化字段缺失，最多 12 个候选、24 类警告、每项最多 16 个依据范围。

所有原文依据区间为 JavaScript UTF-16 code unit offset，左闭右开 `[start, end)`；共享 schema 校验整数、`start >= 0`、`end >= start`、`end <= raw_text.length`。API client 还核对响应原文与请求原文一致。匹配和排除过程保持原文索引，不对原文大小写、Unicode 或空白做规范化。

实现沿用 route → service → 纯解析逻辑。service 仅固定时刻、读取时区并调用纯函数；解析器和词典没有数据库、文件、Shell、网络或工具能力。不新增表、字段、迁移，不改变 RLS，不修改阶段 1A 迁移或数据库快照。parser/dictionary version、依据和解析历史不会提交给保存接口或持久化到数据库。

## 测试、限制与回滚

`SparkyFitnessServer/tests/fixtures/symptom-parser-corpus.json` 在实现规则前冻结 47 条合成语料。契约、Unicode 范围、恶意输入、时区、否定/主体、多症状预期由独立测试固定。期望行为未因实现而降低；格式化只改变排版。代码审查另补充 9 条负数、数值范围、词典外并列表达和非症状活动结束的回归用例，没有改动冻结语料。阶段 1A 的“保存失败保留表单”测试补填了明确开始时间，以适应本阶段取消当前时间默认值的要求。

收尾回归另见 `symptomParser.review.test.ts`，覆盖否定缩写、子女主体、同句内的活动结束、缓解与诱因、模糊时间，以及排除子句后的 UTF-16 依据。`authMiddleware.lastLogin.test.ts` 同时覆盖 Cookie 和 API key：近期合法 Date / 字符串均遵守每小时更新间隔；过期、缺失和非法值触发更新。认证仍沿用既有身份判断，lastLoginAt 只用于更新时间节流，不是会话有效期。

`symptomParser.relief.test.ts` 补充中文改善表达、独立缓解描述、否定／主体／假设边界、诱因排除与 emoji 后的原文依据；解析路由及隔离数据库回归继续验证预览不写入症状记录。

实际运行命令、计数、未执行项和浏览器验收结果以本轮交付报告为准，不复用阶段 1A 的历史计数。证据与账号凭据仅保存到 Git 忽略的本地目录。浏览器永久删除合成记录需单独确认。

规则覆盖有限，可能漏识别、过度排除、无法区分同类症状的多次发作或不常见的主体/否定句；请核对全部字段，复杂表达可手工填写。不提供医学诊断、治疗、处方、趋势、相关性、报告共享、语音、OCR、原生移动页面或离线同步。

回滚只需撤回阶段 1B 代码并重新部署阶段 1A；没有数据库回滚或迁移降级。已经明确保存的记录仍是原有阶段 1A 数据，继续可查看、编辑和永久删除。
