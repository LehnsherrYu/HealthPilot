# 阶段 1A：症状日志 v1

## 范围与验收

基于已经完成的上游能力审计，新增独立的 owner-only 症状日志领域。网页提供新建、历史列表、筛选、查看、编辑、结束事件、删除的完整闭环。沿用认证、应用数据库角色、RLS、共享日期工具和 UI 组件。阶段 1A 不包含自然语言自动解析、AI 调用、关联分析、报告集成或原生移动端页面。

## 数据与契约

新增 `healthpilot_symptom_journal`，外键关联认证用户并随账户删除级联清理。UUID 标识；`raw_text` 保存用户提交的原文（保留空白，不进行推断或标准化），创建后不可通过编辑接口覆盖。修正记录通过结构化字段和备注完成；删除后重新录入可替换原文。

结构化字段为症状名称、部位、强度（未知或 0–10）、开始时间、结束时间、状态、诱因、缓解因素和备注。未知信息使用空值，不编造。状态为 `ongoing`（持续）、`resolved`（已结束）、`unknown`（未知）；只有已结束状态允许且必须填写结束时间，结束不能早于开始。允许纠正状态，包括清除结束时间后重新设为持续。时间以带时区的绝对时间提交、以 `timestamptz` 保存；输入和展示使用用户设置时区。日期筛选按用户时区转换为闭开区间，按开始时间筛选。

原文最多 10000 字符，名称 200，部位 120，诱因/缓解因素各 2000，备注 5000。名称和原文必须包含非空白字符。共享 Zod 契约拒绝未知键、伪造所有者及非法状态组合；SQL 约束提供第二层保障。`version` 用于乐观并发控制，避免两个页面静默覆盖修改。

## 接口

全部挂在 `/api/v2/symptom-journal`，需要现有认证。服务端只接受认证上下文中的本人身份。

- `POST /`：创建，返回 201 和记录。
- `POST /search`：筛选名称、部位、状态、开始日期和结束日期，默认 20 条、最多 100 条，返回 `entries` 和 `has_more`。使用请求体避免敏感筛选出现在 URL 或代理访问日志中。
- `GET /:id`：获取本人记录。
- `PUT /:id`：以完整结构化字段和当前版本更新，原文保持不变。
- `DELETE /:id?version=N`：按版本删除；页面需要确认。

无权限与不存在的记录均为 404；委托/切换上下文为 403；并发版本冲突为 409；验证失败为 400。错误响应只包含固定安全错误文本和代码，不回显请求、SQL、堆栈或 Zod 原始错误。

## 隐私边界

- Tier 1 owner-only RLS 使用 `authenticated_user_id()`；家庭的 diary、medications、reports 等授权均不能读取或修改。没有管理员业务接口例外。
- 路由另外拒绝切换身份、on-behalf-of 头和请求中的所有者键。repository 始终显式传入目标和真实 actor；不使用系统数据库连接。
- 不接入旧症状表、报告、家庭共享、AI 工具、导出或同步。旧数据不迁移、不改变其语义。原生移动端仍只消费原有接口。
- 服务端对此端点只记固定路径、方法、状态类别；请求体、筛选、原文、备注、数据库错误详情不进入日志。覆盖 JSON 解析异常、身份验证拒绝及未知子路由。
- 前端通用 API helper 对该领域禁用内容日志并净化错误，避免全局 Query/Mutation 错误日志间接泄漏。查询缓存按用户隔离，不持久化，退出/切换身份沿用全局清理，页面在委托上下文不挂载。
- 使用独立 `healthpilot` 翻译 namespace 与资源，提供中文/英文，不改机器同步的上游翻译文件。

## 验证计划

先测试共享契约、日期边界和服务行为；再测试路由 CRUD、越权、并发冲突、日志脱敏和错误路径。真实 PostgreSQL 验证新建/升级迁移、表约束及所有者/家庭/其他用户 RLS。数据库测试只在独立测试库使用合成数据。网页测试覆盖表单、筛选、编辑、删除、错误、空态与身份切换；最后在浏览器用合成账号验证中文/英文及完整闭环。运行 server/frontend 的 validate 与 CI 测试、mobile validate、docs build，并检查最终 diff。

仓库旧指南引用的 `docs/content/...` 已迁至 `docs/src/...`；本阶段更新真实位置的共享说明、数据库索引与安全分级。
